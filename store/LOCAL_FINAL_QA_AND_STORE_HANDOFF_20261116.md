# Browser Automation Runner — local final QA and Store handoff

Use the exact successful GitHub artifacts; do not rebuild the Store candidate before
final QA.

## Required artifacts

- `BrowserAutomationRunner-Store-MSIX-UNSIGNED-DRAFT`
- `BrowserAutomationRunner-Windows-with-Chromium`

The Store artifact must include the exact handoff/checksum and customer-readable
third-party notice evidence generated by CI.

## Local preflight

1. Checkout the exact source SHA recorded in `store-product-handoff.json`.
2. Run the full unit suite.
3. Require exact MSIX SHA match against handoff + checksum.
4. Unpack with MakeAppx without weakening Windows trust policy.
5. Require unpacked EXE SHA == handoff EXE SHA.
6. Confirm the bundled `pw-browsers` runtime is present.

## Controlled browser acceptance

Use a harmless test site only:
- offline self-test and bundled Chromium smoke;
- JP/EN first-run flow;
- 100/125/150% DPI;
- navigation + screenshot;
- click/input/wait/select/download on non-sensitive test data;
- output collision/no-overwrite behavior;
- blocked local/private/unsafe navigation;
- failure message and re-run behavior.

## Third-party gate

GitHub must preserve the exact Playwright/Chromium/FFmpeg notice material and package
inventory. The owner/legal review of redistribution terms remains a human gate; do not
turn that flag true merely because the files exist.

After local QA and rights review PASS, reverify Partner Center, complete the remaining
owner fields, run VALIDATE_ONLY and DRY_RUN, then request separate upload approval.
