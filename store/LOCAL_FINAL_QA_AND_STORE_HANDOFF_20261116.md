# Browser Automation Runner — local final QA and Store handoff

Use the exact successful GitHub artifacts; do not rebuild the Store candidate before
final QA.

## Required artifacts

- `BrowserAutomationRunner-Store-MSIX-UNSIGNED-DRAFT`
- `BrowserAutomationRunner-Windows-with-Chromium`

The Store artifact must include the exact handoff/checksum and customer-readable
third-party notice evidence generated by CI.

## Exact artifact staging

Use Windows-all-auto's checked-in Group B registry rather than manually typing the
repository/artifact name:

```powershell
python scripts/pull_group_b_store_product.py `
  --product-id browser-automation-runner `
  --run-id <exact successful GitHub Actions run id> `
  --target-root C:\path\to\group-b-local-inbox `
  --receipt C:\path\to\evidence\artifact-pull-receipt.json
```

The pull receipt is immutable evidence only. It must record no Store submission,
certification, or publication.

## Local preflight

GitHub CI is the primary test environment. Do not make a second full local unit-suite
run a mandatory Store gate after the exact candidate has already passed CI.

1. Use the exact successful GitHub Store artifact and `store-product-handoff.json`.
2. Confirm the local MSIX exists and re-hash it against the handoff + checksum.
3. Use Windows-all-auto's common local pre-upload conveyor to unpack the same MSIX and
   verify Manifest Identity / Publisher / Version / Architecture and the unpacked EXE SHA.
4. Confirm the exact artifact still contains the bundled `pw-browsers` runtime and
   third-party evidence expected by the handoff.
5. Do not rebuild/substitute the package locally.
6. Do not weaken Windows trust policy or add a temporary certificate merely to run an
   unsigned draft.
7. Perform only Windows-specific/product-specific checks GitHub CI cannot prove:
   real bundled-Chromium launch, JP/EN, real OS DPI and harmless physical workflow.

Use Windows-all-auto `scripts/run_store_preupload_readiness.ps1` as the common local
entrypoint. READY means only `READY_FOR_MSIX_UPLOAD_APPROVAL`; it never performs the
Store write.

## Controlled browser acceptance

Use a harmless test site only:
- offline self-test and bundled Chromium smoke;
- JP/EN first-run flow;
- 100/125/150% DPI;
- navigation + screenshot;
- click/input/wait/select/download on non-sensitive test data;
- output collision/no-overwrite behavior;
- blocked local/private/unsafe navigation;
- failure message and re-run behavior.

## Third-party gate

GitHub must preserve the exact Playwright/Chromium/FFmpeg notice material and package
inventory. The owner/legal review of redistribution terms remains a human gate; do not
turn that flag true merely because the files exist.

After local QA and rights review PASS, reverify Partner Center, complete the remaining
owner fields, run VALIDATE_ONLY and DRY_RUN, then request separate upload approval.
